# .gitlab-ci.yml in the PRD repo
prd-lint:
  rules: [{changes: ["prds/**"]}]
  script: dotnet autopilot lint prds/

# .gitlab-ci.yml in the product repo, marked required on the MR
autopilot-verify:
  script: dotnet autopilot verify --prd-hash $PRD_HASH   # hash read from the MR description
  1. Author writes the PRD and opens an MR. CI lint blocks vague conditions. Reviewers approve and the MR merges, which freezes the file.
  2. Author runs autopilot run locally. The gate refuses to start unless GitLab shows the PRD merged, approved and unchanged.
  3. The CLI sends events to the API, so every local run shows up on the shared dashboard. Blocked questions ping the team.
  4. The required CI job repeats the checks on a clean runner. A human approves and merges the code MR.

Check before relying on this: your Copilot admin policy must allow the CLI, and per-run credit numbers depend on what the CLI reports.
